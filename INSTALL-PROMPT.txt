Install and start Virtual Office on the user's computer

Official repository: https://github.com/peipeichan605-cpu/virtual-office
Release: 0.2.2-preview.1
Entry point for agents: AGENTS.md at the root of the repository.

If the user asks for installation, perform the steps with your local tools and report what actually worked. A repository link and a short installation request are enough. Use the user's preferred language when handing over.

1. Identify the host and prerequisites

Confirm that your tools operate on the computer the user intends to host OFFICE. A cloud sandbox has its own localhost. Choose a writable folder and inspect that location for an existing install. Full setup needs a healthy Python 3.10+ with ssl, sqlite3, venv and plistlib, Node.js 22.13+, a compatible local Codex app-server, and network access for pinned UI files and the Cursor SDK. The pinned Cursor SDK requires x64 Python on Windows. An existing Python 3.9 OFFICE core may use a separate compatible interpreter for the SDK.

Prefer healthy programs already installed. On Windows use the verified native codex.exe. A .cmd or .bat shim cannot serve as the app-server executable. Use official installation methods for missing prerequisites and pause at the specific step where the owner must sign in or give OS approval. Use this computer's own accounts and executables. Keep the host's VPN and firewall settings as they are for local installation.

2. Obtain the requested release

For an empty target folder, clone the requested tag or the current version listed at the top of the README. This version can be cloned with the following command. Replace the destination before running it.

git clone --branch v0.2.2-preview.1 --depth 1 https://github.com/peipeichan605-cpu/virtual-office.git "<installation-folder>"

Record VERSION and git rev-parse HEAD. For the ZIP route, obtain the named installation ZIP and matching .sha256 file from the same release page, verify the full SHA-256, then extract into a new folder. These public downloads require no GitHub credentials. Preserve .gitattributes when checking out on Windows. The UI hashes depend on the exact file contents.

Read AGENTS.md, README.md, docs/QUICKSTART.md, the relevant platform guides, NOTICE.md, office.py and setup_ui.py. Use the config and files belonging to this installation.

3. Recognize an existing OFFICE

Identify any existing .office/ folder, custom private data directory or running instance before cloning or initializing. Reuse a healthy installation of the requested version. For an upgrade, follow docs/UPGRADING.md. Let active work finish, back up private data, preserve local changes and the original config, and move the old generated public/ directory to a backup before rebuilding the UI. Keep backups outside the public checkout. Reinitialization would create a different OFFICE.

4. Initialize and start a fresh OFFICE

Use a verified free unprivileged loopback port, normally 4318. Run each command in the folder containing office.py. Replace <port> with a number and, on Windows, use the verified Python or py -3.

python3 setup_ui.py
python3 office.py --config .office/config.json init --port <port>
python3 office.py --config .office/config.json setup-platforms
python3 office.py --config .office/config.json setup-platforms --check
python3 office.py --config .office/config.json start
python3 office.py --config .office/config.json status

Proceed after each successful step. setup_ui.py verifies all pinned assets and returns ui_installed=true. setup-platforms prepares the pinned Cursor SDK in this installation and checks Node.js and Codex. The Grok SDK source is bundled. Resolve any reported prerequisite and recheck until runtimes_ready=true. An installed Cursor Desktop app and an installed Cursor SDK are separate things. OpenRouter free text uses the Python core. The owner enters their key in their own OFFICE if they select that route.

Each office.py command takes --config before its subcommand. Reuse an existing installation's original config path. On Windows, if the terminal will terminate a child process at exit, open Start Office.cmd from Explorer for an initialized default installation, or run start from a normal PowerShell window using the same config. Save the run ID, PID, log path and stop command from the start receipt. The standard service runs in the background without adding a startup task.

5. Verify the installation

Check the same instance for state=running and local_ok=true. A fresh roster has selected=0. Verify that /office/ loads on the chosen port and obtain the private URL.

python3 office.py --config .office/config.json url

Open it in a browser on the target host and check the 3D lobby, controls and empty roster. With terminal-only access, report the HTTP result and identify the remaining visual check. Read only this installation's relevant logs and keep secrets out of the report.

6. Hand the office to its owner

Provide the release and commit or archive digest, folder, runtime results, service and browser checks, and instructions to reopen and stop this instance. A newly started instance also has a run ID, PID and log path. Show the private dashboard only to the owner. Keep .office/, pairing codes, keys and chats out of GitHub and shared logs.

The owner chooses an agent using Invite Agent or New conversation. Existing App chats, Cloud Agents and OFFICE-managed sessions have different scopes. Account sign-in, any one-time approval and a real message/reply check belong to the selected route. The owner's choice of a phone is optional. If requested, follow docs/MOBILE-QUICKSTART.md for official Tailscale installation, same-account login, Connected status, separate view/send permissions and QR pairing. Remembering a phone is the owner's choice.

If an essential step could not be completed, report the specific cause, what passed and the smallest action still needed.
